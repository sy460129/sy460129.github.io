# 1. 커널 모드와 유저 모드 (CPU Previlege Levels)
CPU는 실행 권한을 나누어 관리한다.

x86_64 아키텍처에서는 Ring 0 ~ 3으로 구분한다.

```
+--------------------------------------------------------+
| Ring 3 : User Mode (일반 응용 프로그램, 웹 브라우저 등) |
|   - 하드웨어 직접 접근 불가, 제한된 메모리 영역 접근    |
+--------------------------------------------------------+
| Ring 1, 2 : (보통 사용되지 않음 / 하이퍼바이저 등)      |
+--------------------------------------------------------+
| Ring 0 : Kernel Mode (리눅스 커널, 드라이버)            |
|   - 모든 CPU 명령 실행 가능, 모든 메모리/하드웨어 제어  |
+--------------------------------------------------------+
```

- 유저 모드 (Ring 3): 일반 프로그램이 실행되는 영역. 디스크에 파일을 쓰거나 네트워크 패킷을 보내는 등 하드웨어 제어가 필요한 경우 커널에 요청을 보낸다.

- 커널 모드 (Ring 0): OS의 핵심 코드와 드라이버가 실행되는 최고 권한 영역.



# 2. System Call
유저 공간의 프로그램이 read, write, fork, brk, mmap 등 커널의 도움이 필요할 때 사용하는 인터페이스.

실행 흐름은 아래와 같다.

1. 요청 준비: 유저 프로그램이 RAX에 시스템 콜 번호를 넣고, 매개변수를 레지스터에 설정
2. 모드 전환: syscall 어셈블리 명령어를 실행. CPU는 즉시 Ring 3에서 Ring 0으로 전환.
3. 커널 스택 전환 및 핸들러 호출: CPU 실행 흐름이 커널의 entry_SYSCALL_64 핸들러로 이동.
				유저 레지스터 상태를 커널 스택에 저장.
4. 검증 및 실행: 커널은 유저가 전달한 인자가 유효한지 검사한 후 해당 작업을 수행
5. 복귀: 작업 완료 후 sysret 명령어를 통해 유저 모드로 복귀


3. 프로세스와 권한 관리 (task_struct와 cred)
커널은 실행 중인 모든 작업을 task_struct라는 구조체로 관리.

- task 구분: 유저 공간에서는 프로세스와 쓰레드를 구별하지만, 커널 내부에서는 모두 스케쥴링 단위인 task_struct 객체로 동일하게 다룬다.

- 권한 객체 (cred): task_struct 내부의 cred 포인터가 해당 task의 권한 정보를 담고 있다. 

```
+-------------------------------------------------------+
|                    task_struct                        |
|                                                       |
|   pid: 1001                                           |
|   tgid: 1001                                          |
|   mm:  0x7fff8000... (유저 메모리 주소)               |
|                                                       |
|   real_cred ------+                                   |
|   cred -----------|---> +---------------------------+ |
|                   |     |       struct cred         | |
|                   +---> |                           | |
|                         |  uid: 1000  (실제 사용자) | |
|                         |  gid: 1000                | |
|                         |  euid: 0    (실행 권한)   | |
|                         |  egid: 0                  | |
|                         |  cap_inheritable          | |
|                         |  cap_permitted            | |
|                         |  cap_effective            | |
|                         +---------------------------+ |
+-------------------------------------------------------+
```

# 4. 커널 메모리 관리와 할당자
커널은 가상 메모리를 사용하며, 물리 메모리와 가상 메모리 간의 변호나은 Page Table을 통해 이루어진다.

유저 가상 주소 (User Space)    : 0x0000000000000000 ~ 0x00007FFFFFFFFFFF
커널 가상 주소 (Kernel Space)  : 0xFFFF888000000000 ~ 0xFFFFFFFFFFFFFFFF
- kmalloc(): 커널 내부에서 작은 크기의 연속된 물리 메모리를 할당. 내부적으로는 slub allocator를 거쳐 할당.

- vmalloc(): 물리적으로는 연속되지 않더라도 가상 메모리 상에서 연속된 큰 메모리 영역을 할당.

- kfree(): kmalloc으로 할당받은 메모리 해제.



# 5. 핵심 커널 보호기법
- KASLR: 부팅 시 커널 코드와 구조체가 메모리에 로드되는 기본 주소를 임의로 변경.

- SMEP: 커널 모드 상태에서 유저 공간 메모리에 있는 코드를 실행하려고 하면 차단.

- SMAP: 커널 모드 상태에서 명시적인 허용 명령어 없이 유저 공간 메모리 R/W시 차단.

- KPTI: 유저 모드 실행 중에는 커널 Page Table 대부분을 분리하여 커널 메모리 주소 유출 방지.
